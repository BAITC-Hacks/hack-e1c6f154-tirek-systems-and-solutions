# hack-e1c6f154-tirek-systems-and-solutions
Hackathon team repository for Tirek Systems and Solutions

## Tirek: рекомендации по пополнению склада

Цель прототипа — быстро сформировать объяснимые рекомендации закупщику на основе
свежих данных, ML-прогноза и индивидуальной экономики каждого товара.
Менеджер проверяет рекомендации, корректирует их и утверждает экспорт заказа.

## Запуск платформы

Реализован интерфейс на **React + TypeScript + Vite** и backend на **FastAPI + SQLite**.
Есть обзор закупок, рекомендации с поиском и фильтрами, карточка товара, проверка XLSX,
корректировки, утверждение снимков и экспорт CSV. Демо содержит 12 синтетических товаров.
ML-прогноз и нормализация партнёрских файлов подключаются отдельно.

Первый запуск, PowerShell из корня репозитория (Node.js 20.19+ и Python 3.11+):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
npm --prefix frontend ci
.\scripts\dev.ps1
```

Если зависимости уже установлены, достаточно `.\scripts\dev.ps1`.
Приложение: **http://127.0.0.1:5173**. API: **http://127.0.0.1:8000/docs**.
`Ctrl+C` останавливает оба сервера, логи находятся в `.logs/`.
Для хранения на другом диске: `.\scripts\dev.ps1 -DataDir 'D:\tirek-data'`.

Раздельные команды запуска: [frontend/README.md](frontend/README.md) и
[backend/README.md](backend/README.md). Точки подключения своей модели:
[docs/ml-integration.md](docs/ml-integration.md). Дизайн и выбранные приёмы:
[DESIGN.md](DESIGN.md).

**Быстрый сценарий:** откройте рекомендации → выберите товар → «Корректировка» →
сохраните количество с причиной → отметьте позицию → «Утвердить» → скачайте CSV.
Снимок сохраняется в SQLite и доступен после перезапуска.

В первые 15 минут команды принимают или совместно корректируют контракт.
После этого платформа работает с синтетическими [примерами](contracts/examples/),
а бэкенд реализует тот же формат. Первый общий сценарий должен работать к T+90 мин.

**Текущее состояние:** платформа и HTTP API реализованы. Отдельно в `model/`
сохранён обученный CatBoost на продажах SE: 565 товаров, горизонт 28 дней,
веса, временная проверка и команды пересчёта по свежей истории. Baseline пока точнее;
ограничения и результаты приведены в [описании модели](model/README.md).

Модель ещё не подключена к HTTP API и интерфейсу. Платформа использует явно помеченный
синтетический сценарий; сетевые ошибки не подменяются примерами. Реальные XLSX
проверяются и сохраняются, но без нормализатора не объявляются готовым набором
для прогноза. Подготовлены отдельные офлайн-модули регулярного спроса со stockout-коррекцией,
расчёта заказа, уровней остатков и проверки JSON/evidence ответа ИИ. Подключение этих
модулей к API, проверка stockout на реальных данных и реальный вызов LLM остаются
отдельным этапом. JSON-примеры контрактов не являются результатами обучения.

Партнёрские Excel/PDF/ZIP, API-ключи и реальные данные клиентов в репозиторий не добавляем.
Порядок локального подключения данных указан в ТЗ бэкенда.

Проверка схемы и синтетических примеров описана в [contracts/README.md](contracts/README.md).
