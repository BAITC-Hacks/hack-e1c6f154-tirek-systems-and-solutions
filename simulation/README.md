# Симуляция уровней остатка

Открыть `simulation/index.html` в браузере. Сборка, сеть, API-ключи и установка
зависимостей не нужны. Либо из корня репозитория:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Затем открыть `http://127.0.0.1:8765/simulation/`.

Для передачи одним файлом собрать автономный HTML, указав путь результата:

```sh
python3 scripts/export_simulation.py /tmp/tirek-stock-simulation.html
```

Полученный файл открывается в браузере без соседних файлов и без сети.

Все данные синтетические; состояние хранится только в памяти вкладки. Перезагрузка
страницы, смена профиля и «Начать заново» сбрасывают сценарий. Журнал показывает
последние 12 записей. Никаких заказов, внешних уведомлений или записей в учётную систему.

## Сценарий демонстрации

1. «Демо: 60 → 39 → 29 → 19» выполняет три выдачи и показывает warning → high → critical.
2. Указать 3 и нажать «Принять товар»: 22%, критический сигнал сохраняется.
3. Принять ещё 1: 23%, уровень становится high. Это гистерезис 3 процентных пункта.
4. Повторить последнее событие: остаток и ревизия не изменяются, нового сигнала нет.
5. Проверить резерв и отгрузку из резерва: доступный запас не списывается дважды.
6. Выбрать другой профиль или изменить цель/пороги с причиной. Пустая цель означает
   unknown; изменение политики имеет отдельную запись и не выглядит как продажа.

`monitor-core.js` — независимая эталонная логика для сценария. Она возвращает формы
State/EventResult из дополнительного OpenAPI, но HTTP-эндпоинты не реализует.
Дедупликация и ревизии существуют только в памяти: backend должен перенести их в
атомарное постоянное хранилище. recalculation_requested=false: симулятор не запускает
несуществующий ML/LLM или очередь расчётов. Статус остатков не заменяет прогноз риска.

Проверка бизнес-логики, Node.js 18+:

```sh
node --test simulation/monitor-core.test.cjs
```
