# HTTP-контракт и примеры

OpenAPI 3.1: [openapi.yaml](openapi.yaml). Контракт реализованного
[API платформы](../backend/README.md); проверка схемы сама по себе
не проверяет работающий сервер.

Дополнение [stock-monitoring.openapi.yaml](stock-monitoring.openapi.yaml) задаёт события,
индивидуальные пороги и переходы уровня. Два синтетических примера — в
[monitoring-examples/](monitoring-examples/). Проверяются той же командой.

Все JSON в [examples/](examples/) синтетические. Пример таблицы содержит одну
допустимую позицию и одну позицию без актуального остатка у другого поставщика.
Данные не являются прогнозом обученной модели и не подтверждают качество алгоритма.
`additional-context.json` показывает формат отдельных входов, а не полный датасет
для тестов stockout и выбросов. Отдельные проверки этих алгоритмов находятся
в [regular_forecast](../model/regular_forecast/README.md).

При quantity=null интерфейс показывает причину, а не ноль. Пример утверждения относится
к исходной revision=1; после PATCH нужно использовать новую ревизию из ответа сервера.
SHA-256 в отчёте — синтетические значения, не хеши партнёрских файлов.

## Проверка

Из корня репозитория, Python 3.11+:

```sh
python3 -m venv .venv-contract
.venv-contract/bin/pip install -r contracts/requirements-dev.txt
.venv-contract/bin/python scripts/validate_contract.py
```

Проверяются спецификация OpenAPI, соответствие всех десяти JSON заявленным схемам,
связность примеров, арифметика партий/стоимости, отсутствие несуществующих ссылок
в Markdown. Это проверка документации и примеров; проверки приложения
запускаются отдельно по [README](../README.md#автоматические-проверки).

Семантические правила вроде запрета утверждения needs_data, обработки stockout,
временной проверки ML и отсутствия синтетики в operational проверяются отдельно
от схем. Границы реализации и доказательства по
[матрице кейса](../docs/requirements-matrix.md) описаны в
[анализе сдачи](../docs/submission-analysis.md).
