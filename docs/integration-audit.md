# Аудит платформы, 23.09.2026

Проверены platform-spec, model-backend-spec, requirements-matrix и текущая интеграция.
Это аудит работоспособности и границ реализации, а не новая оценка точности модели.

Дополнение после этого аудита: выполнен сквозной прогноз по реальным XLSX IEK,
подключён транспорт LLM и исправлено отображение наблюдаемых рядов.
Текущее состояние и новые проверки: [live-forecast.md](live-forecast.md).

## Исправлено

- Vite запускался без действующего API-прокси и возвращал HTML с кодом 200.
  Конфигурация теперь указана явно; запуск проверяет JSON через прокси. Клиент
  распознаёт HTML и повреждённый JSON, показывает понятную ошибку и позволяет повторить.
- Python 3.14 содержал только зависимости платформы, поэтому импорт модели падал.
  Установлено отдельное окружение Python 3.12, добавлен requirements-ml.txt;
  dev.ps1 предпочитает .venv-ml. Доступность адаптера и весов проверяется в capabilities.
- Чтение UTF-8 нормализованных файлов зависело от системной кодировки Windows.
  Адаптер теперь явно читает UTF-8; тест проходит с кириллическим названием товара.
- Git autocrlf менял байты frozen selection, коэффициентов и исходников модели,
  из-за чего проверка SHA-256 блокировала настоящий прогноз. `.gitattributes`
  сохраняет исходный LF. Веса и записанные контрольные суммы не изменены.
- UI всегда показывал демо и сценарий, предлагал только демонстрационные категории
  и не передавал экономические параметры. Для загруженных наборов доступны исходные
  коды, режим, дата, срок и JSON-массивы политик/экономики/прироста.
- Переход из отчёта выбирает соответствующий набор; нормализованный набор больше
  не подписан как требующий нормализации. Имена файлов соответствуют требованиям SE.
- Добавлен рабочий фильтр поставщика; режим истории берётся из утверждённого снимка.
  Ошибки проверки API содержат конкретные поля. Повтор импорта после завершённой
  ошибки получает новый ключ, а сетевой повтор сохраняет идемпотентность.

## Проверки

- `python -m pytest backend/tests model -q`: 173 теста, 763 subtests успешно.
  Есть предупреждение стороннего Starlette о будущем отказе от httpx в TestClient.
- `python scripts/validate_contract.py`: обе OpenAPI-спецификации и 12 примеров валидны.
- `npm run build`: TypeScript и production-сборка проходят.
- Playwright: 11 сценариев — прокси, страницы, поиск/карточки, MOQ, корректировка,
  утверждение и реальные байты CSV, мобильный экран, сетевой сбой, HTML/невалидный
  JSON, новый расчёт, настоящий импорт неполного XLSX, форма реального набора,
  состояние адаптера и фильтр поставщика. Используется отдельная локальная база.
- HTTP-тест адаптера проходит путь задача → список → карточка → отказ в утверждении
  неполных условий. Прогноз и входные файлы в нём заменены контролируемыми входами,
  а production decision core работает без подмены. Это не проверка качества прогноза.
- Отдельный smoke-тест действительно загружает frozen selection, признаки и веса SE,
  формирует прогноз на синтетической истории. Он проверяет совместимость окружения
  и контрольных сумм, не измеряет точность модели на партнёрских данных.
- UI-тест параметров реального набора использует явно тестовый ответ workspace и
  проверяет тело POST и ошибки полей, не выдаёт fixture за импорт партнёра.

## Что остаётся по ТЗ

| Требование | Фактическое состояние / следующий шаг |
| --- | --- |
| Сквозной импорт шести реальных XLSX → прогноз → закупка | Код соединён; на этой машине исходных файлов нет. Нужен прогон совместимого полного набора с фиксацией времени и отчёта. |
| MH1: история, остатки, путь, категории, прирост | Поля и decision core соединены; неполные условия поставки и неизвестная область склада блокируют окончательное утверждение. |
| MH2: сезонность/рост | Forecast v2 и сохранённые веса доступны; новые метрики в этом аудите не рассчитывались. |
| MH3/MH4: stockout и клиентские выбросы | Отдельный regular_forecast протестирован. Встроенный адаптер forecast v2 не применяет соответствующий дополнительный контекст и сообщает об этом. Нужна отдельная интеграция. |
| MH5: поставщики и объяснения | Таблица группирует и фильтрует поставщиков; API поддерживает расчёт SE и прогноз IEK. Для заказа IEK не хватает текущих остатков. |
| Остатки 40/30/20%, события/симуляция | Есть контракт и офлайн-правила. HTTP-сервис событий и оперативное обновление UI пока отсутствуют. |
| LLM-проверка | Транспорт подключён, нужен настроенный провайдер. На этой машине живой вызов пока не подтверждён; UI не показывает фиктивное одобрение. |
| Экспорт в 1С | Неизменяемый CSV работает. Совместимость с конкретной конфигурацией 1С не подтверждена. |
| Совместная удалённая работа в приложении | Git-синхронизация согласована. Само приложение пока локальное, без аутентификации и разделения пользователей. |

Тесты и изменения UI не заменяют эти незавершённые требования.
