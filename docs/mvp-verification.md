# Проверка работающего MVP · 23.09.2026

Исходное ТЗ: кейс HackAlem AI «Автоматизация формирования заказов поставщикам».
Проверка разделяет запуск программы, бизнес-инварианты и качество прогноза.
Рабочие исходники партнёра не найдены в текущем checkout, Downloads и Desktop;
новые проверки выполняются на явно синтетических Excel. Это не повторная
проверка на исходных продажах партнёра.

| Обязательное требование | Реализация | Проверяемое свидетельство |
| --- | --- | --- |
| История, остаток, путь, категория, прирост | Нормализатор + forecast v2 + decision core | Тесты источников/адаптера и чувствительности решения к входам |
| Сезонность и устойчивый рост | Сохранённые модели v2; регулярный прогноз с историческим выбором метода | model/forecast_v2 и model/regular_forecast тесты; отдельные метрики в REPORT.md |
| Компенсация stockout | AdditionalContext.stockout_intervals, поправка экспозиции спроса | Сравнение с расчётом по сырым наблюдениям, без превращения отсутствия товара в нулевой спрос |
| Исключение крупного разового клиента | client_labels по ID строки, недельные окна клиента | Разовая покупка 300 шт. исключается в учебном XLSX; исходные события сохранены |
| Список по поставщику с обоснованием | Рекомендации, карточка, подтверждённый снимок и CSV | Браузерный путь от XLSX до выгрузки; форма не отправляет заказ поставщику |

Новые аккаунты получают отдельные наборы, расчёты, idempotency, CSV и каталоги
загрузок. Ключ нельзя получить через API. Cookie HttpOnly/SameSite, пароль
PBKDF2-SHA256 (600 000 итераций + индивидуальная соль), CSRF для мутаций,
ограничение попыток входа и регистрации. Действия сохраняют ID автора.
Дизайн паролей сверялся с [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Проверено локально 23.09.2026: Python 3.12, Node 22, настоящий Chromium.

- Backend после объединения: **162 теста и 10 подтестов**, включая изоляцию аккаунтов
  и складских событий, CSRF, импорт, расчёт, снимки, AI-квоты и помощника.
- Модель после объединения с изменениями команды: **181 тест и 966 подтестов**;
  это проверки алгоритмов, не новый бизнес-holdout.
- Браузер: **17 сценариев** — 13 прежних платформенных и 4 сервисных (аккаунты,
  мониторинг остатка, мобильный вход, SE и IEK XLSX → ML → утверждение → CSV).
  SE: шесть учебных файлов / четыре товара; IEK: три файла / три единицы измерения.
  Проверены `forecast.method != contract_example`, исключение 300 шт., скачивание ZIP,
  чтение JSON-контекста и сохранение заказа после перезагрузки.
- Ещё **2 повторных браузерных проверки** аккаунта и мониторинга прошли на готовой
  сборке через API-порт 8000, без Vite; CSP и same-origin cookies не ломают приложение.
- TypeScript и production-сборка Vite прошли; OpenAPI/примеры проходят валидатор.
- Скриншоты локального прогона сохранены в `.local-data/evidence/` и не публикуются в Git.

## Воспроизведение

```powershell
.\.venv-ml\Scripts\python.exe scripts/generate_sample_data.py --output .local-data/samples
.\.venv-ml\Scripts\python.exe scripts/generate_sample_data.py --supplier iek --output .local-data/samples-iek
.\.venv-ml\Scripts\python.exe -m pytest backend/tests model -q
npm --prefix frontend run build
```

Браузерные проверки запускайте с отдельным DATA_DIR. Для `auth.spec.ts` и
`ml-workflow.spec.ts` авторизация включена. Старый `platform.spec.ts` требует
изолированный API с `TIREK_AUTH_DISABLED=1`. Не запускайте их на рабочей базе.

## Границы MVP

Пять must-have проверяются при наличии соответствующих входов. Если в реальных
выгрузках нет точных периодов отсутствия или клиентских меток, качество их
восстановления на реальном бизнесе не доказано. Метрики v2 не пересчитывались на
новом партнёрском holdout; опубликованные ошибки остаются действующими.
Одна траектория спроса не даёт гарантии вероятностного уровня сервиса.

Внешний ИИ проверяется в автоматических тестах через обозначенный тестовый
провайдер; живой вызов требует нового серверного ключа и доступной модели.
Раскрытый в переписке ключ не используется. Программа работает и без него.
Docker-образ подготовлен; результат его сборки не заявляется без прогона Docker.
Складской мониторинг сохраняет пороговые переходы и намерение пересчёта; worker
автоматического пересчёта не подключён, симуляция не объявляется живой интеграцией с 1С.
Нет почтового восстановления, приглашений/ролей команды, коннектора 1С,
автоматической рассылки поставщикам и распределённой очереди расчётов.
