## Повторный запуск

1. Запустите `scripts/dev.ps1` с окружением `.venv-ml`; авторизация включена по
   умолчанию. Зарегистрируйтесь или войдите в своё рабочее пространство.
2. В «Источниках данных» выберите **IEK**, загрузите XLSX
   с оригинальными именами. Для прогноза обязательны `Динамика*.xlsx` и
   `Ежемесячные продажи*.xlsx`; остальные роли сохраняются с явным отчётом об использовании.
3. В отчёте нажмите «Перейти к расчёту». Оставьте дату источников и запустите прогноз.
4. Откройте рекомендации: таблица разбита по 50 строк, есть поиск и фильтр поставщика.
   В карточке показаны фактическая история и прогноз. Отсутствующий регулярный ряд
   не скрывает наблюдаемые продажи, отсутствующие интервалы не заменяются нулём.

Для импорта через тот же API создайте аккаунт в интерфейсе, затем укажите его
почту. Пароль запрашивается скрытым интерактивным вводом, не передаётся аргументом
командной строки и не сохраняется в файлах. Cookies и CSRF используются только
в текущем HTTP-клиенте; новый импорт требует нового входа:

```powershell
.\.venv-ml\Scripts\python.exe -X utf8 scripts/import_local.py 'C:\path\IEK' --supplier iek --email buyer@example.kz --forecast
```

Откройте платформу под тем же аккаунтом: импорт находится только в его
пространстве. Без `--email` сервер с авторизацией вернёт понятную ошибку до
загрузки файлов. Адрес другого сервера задаётся `--api https://tirek.example/api/v1`;
вход по открытому HTTP разрешён только для loopback (`127.0.0.1`, `::1`,
`localhost`). Встроенные в URL логин/пароль, query и fragment не принимаются;
редиректы при входе не выполняются. В изолированной локальной проверке с явно
заданным `TIREK_AUTH_DISABLED=1` CLI работает без почты и пароля.

CLI `--forecast` запускает прогноз без выбранных пользователем политик запаса.
Для расчёта заказа с такими политиками импортируйте файлы, затем задайте параметры
в интерфейсе. Для синтетических наборов CLI выбирает сценарный режим, для
наблюдаемых — операционный. Пароли и ключи не добавляйте в JSON-контекст.

Динамика IEK содержит более 171 тысяч строк. Лимит листа поднят до 250 тысяч;
ограничения 30 МБ исходников, 120 МБ распакованного XLSX и 256 столбцов сохранены.

Обычный файл «Путь ИЭК» содержит поступления, а не актуальный свободный остаток.
В таком наборе остаётся режим `FORECAST_ONLY`: прогноз доступен, количество и
стоимость заказа — `null`, утверждение недоступно. Месячные остатки не подменяют
текущий снимок.

Для полного расчёта IEK теперь можно добавить явный стандартный складской снимок
в XLSX роли `current_stock_inbound`, например с заголовками:

`Код`, `Номенклатура`, `Ед.`, `Склад`, `Дата снимка`, `Остаток`,
`Зарезервировано`, `Свободный остаток`, `Минимальная партия`, `Кратность`,
`Шаг единицы`, `Категория`, `Цена закупки KZT`, `В пути`, `Дата поступления`.

Указывайте подтверждённые значения. После распознавания снимка отчёт содержит
`CURRENT_STOCK_TEMPLATE_APPLIED`; общая блокировка `FORECAST_ONLY` снимается.
Далее используются общие правила заказа SE/IEK: политика категории или экономика,
даты поступлений, текущий запас, MOQ и кратность. Политики, экономические параметры
и прирост задаются в форме расчёта. Если данные отсутствуют для отдельных SKU,
эти позиции остаются заблокированными. Учебный архив IEK доступен по кнопке
«Скачать учебный набор»; синтетические примеры подтверждают работу нового пути,
но не заменяют повторный прогон партнёрских файлов.

## Подключение LLM

Транспорт использует Chat Completions и JSON-ответ с последующей проверкой полей,
ссылок на факты, правил и ревизии. Основа: [OpenAI Docs — JSON mode](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode).
Имена моделей не зашиты: укажите модель, доступную вашему аккаунту.

Создайте локальный `backend/.env` (он исключён из Git):

```dotenv
TIREK_LLM_BASE_URL=https://api.openai.com/v1
TIREK_LLM_MODEL=YOUR_AVAILABLE_MODEL
TIREK_LLM_API_KEY=YOUR_LOCAL_SECRET
```

Можно использовать совместимый локальный endpoint: для localhost ключ необязателен.
После перезапуска сервера `/health.llm_available` показывает наличие конфигурации;
это не обещание доступности внешнего сервиса. В карточке → «Обоснование» →
«Проверить с ИИ» выполняется настоящий вызов провайдера. Внешнему провайдеру
передаётся компактный контекст выбранного товара; полные XLSX не отправляются.

При отсутствии настроек кнопка отключена с объяснением. Успешное заключение
содержит модель, причины и действие. Timeout, HTTP-ошибка, выдуманные evidence/rule ID,
неподтверждённые числа и изменившаяся ревизия не превращаются в одобрение.
ИИ не меняет количество и не утверждает заказ. Автоматическая проверка расчёта
по `request_ai_review=true` ограничена первыми пятью позициями, остальные проверяются
по одной из карточки. На сетевой сбой допускается один повтор.

Настройки конкретной машины не являются частью публичного проекта. Наличие
ключа или флаг готовности не доказывает успешный внешний вызов. Без провайдера
чат «Помощник» использует явно помеченную локальную справку. MockTransport-тесты
проверяют запрос/ответ и отказ при неверных данных; это не живой внешний вызов.

## Проверки и границы протокола

- Исторический протокол: 180 Python-тестов и 763 subtests, импорт IEK → настоящие веса → HTTP-ответ;
  сохранение/конфликты ревизий ИИ; существующие правила закупки и модели.
- Историческая production-сборка TypeScript/Vite.
- Исторические 13 браузерных сценариев платформы, кнопка ИИ с явным тестовым ответом и график
  наблюдаемых продаж при `regular_sales=null`.
- Историческая проверка браузером на сохранённом реальном расчёте: 2 149 позиций,
  страницы по 50, карточка ML, исходные данные и мобильный экран без переполнения.

Актуальные команды разделены на сервисные проверки с авторизацией и локальную
регрессию без неё: [frontend/README.md](../frontend/README.md). Изменения CLI
проверяются отдельно в `backend/tests/test_import_cli.py`: cookies/CSRF,
обязательность входа, защищённый транспорт и отсутствие пароля в ошибках.
