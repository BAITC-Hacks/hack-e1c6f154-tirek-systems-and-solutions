# Проверка Tirek для жюри

## 1. Запуск без данных партнёра

Выполните [команды из README](../README.md#быстрый-запуск) и откройте
http://127.0.0.1:5173. Регистрация и API-ключи не нужны. Демо создаётся автоматически:
12 синтетических товаров, склад Алматы, горизонт 28 дней.

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть `/api/v1/health` на порту 8000 | JSON с `status: ok` |
| Открыть обзор на порту 5173 | Состояние склада, график спроса и рекомендации |
| «Новый расчёт», синтетический набор, стандартные параметры | Новый расчёт в сценарном режиме |
| В рекомендациях найти `EZ9F34116` | Одна строка и карточка автоматического выключателя |
| Посмотреть историю и обоснование | Синтетический прогноз, остаток, партия и причины решения |
| В «Корректировке» указать `13` и причину | Ошибка кратности 12, правка не сохраняется |
| Указать `156`, причину «Уточнён план монтажа», сохранить | Новая итоговая партия и ревизия расчёта |
| Выбрать строку, утвердить и скачать CSV | Снимок и файл с итоговым количеством 156 |
| Открыть «Историю решений», скачать снова | Тот же утверждённый снимок |
| Найти `A9R41240` | Прочерк вместо неизвестного остатка, причина невозможности расчёта |
| Открыть «Источники данных» | Источники, качество и явная маркировка синтетики |

Перезапустите серверы с тем же `DATA_DIR`: утверждение должно сохраниться.
Сценарий автоматизирован в [Playwright](../frontend/e2e/platform.spec.ts).
Он проверяет интерфейс и согласование заказа; качество ML оценивается отдельно.

## 2. Что экспортируется

CSV: **UTF-8 с BOM**, разделитель **`;`**, одна строка на утверждённый товар.
Файл создаётся из неизменяемого снимка. Позднейшая корректировка расчёта не меняет
ранее утверждённый экспорт. Формулы в текстовых полях экранируются.

```text
approval_id;calculation_id;revision;mode;data_as_of;supplier_id;sku;name;unit;recommended_quantity;final_quantity;override_reason;urgency;reason;model_id;policy_version;economics_source
```

Сверьте `sku`, `final_quantity`, `override_reason` и `revision`.
`recommended_quantity` сохраняет исходную рекомендацию, `final_quantity` —
принятое менеджером количество. CSV не отправляется поставщику.
Совместимость с конкретным импортом 1С требует проверки у партнёра.

## 3. Реальный расчёт при наличии XLSX

Для IEK уже доступен отдельный прогноз продаж по штукам, метрам и упаковкам;
сквозной путь проверен на 2 149 товарах. Выберите IEK в форме импорта.
Количество закупки остаётся неизвестным без актуального свободного остатка.
[Повторный запуск IEK и настройка LLM](live-forecast.md).

Партнёрские файлы распространяются отдельно от Git. Встроенный адаптер принимает
шесть ролей Systeme Electric; структура и исходные названия должны соответствовать
выгрузке. Файл текущего склада должен сохранять дату снимка в названии.

| Роль | Шаблон имени | Назначение |
| --- | --- | --- |
| `sales_transactions` | `Динамика*.xlsx` | Дневные продажи |
| `sales_monthly` | `Ежемесячные продажи*.xlsx` | Месячная история и сверка |
| `stock_monthly` | `Ежемесячные остатки*.xlsx` | Аудит доступности, без выдуманных дат stockout |
| `seasonality` | `Сезонность*.xlsx` | Сезонный контекст и аудит |
| `moq` | `MOQ*.xlsx` | Известные ограничения; имя файла само по себе не подтверждает MOQ |
| `current_stock_inbound` | `Товар в пути*.xlsx` | Остаток, резерв, категория и поступления |

1. Установите Python-зависимости из README. Встроенные адаптеры:
   `backend.app.ml_adapter:normalize_dataset` и
   `backend.app.ml_adapter:TirekCalculationPipeline`.
2. Загрузите файлы в «Источниках данных»; при необходимости передайте JSON-контекст
   по схеме [AdditionalContext](../contracts/openapi.yaml).
3. Дождитесь отчёта импорта. Проверьте число SKU, даты, роли, предупреждения
   и `calculation_allowed`. Неполный комплект не становится готовым набором.
4. Создайте расчёт через `POST /api/v1/calculations` в Swagger на `/docs`.
   Основа тела — [CalculationRequest](../contracts/examples/calculation-request.json):
   замените `dataset_id`, дату и параметры на свои. Передайте уникальный
   `Idempotency-Key`. Нужны экономические профили либо явные политики категорий;
   синтетические параметры допускаются только в `scenario`.
5. Дождитесь `succeeded` через `GET /api/v1/jobs/{job_id}` и прочитайте
   рекомендации созданного расчёта по API. В интерфейсе выберите созданный расчёт.
6. Сверьте источник, метод и версию модели, историю, остаток, поступления, причины
   и ограничения. При неизвестном MOQ ожидаемо предварительное количество:
   невозможность утвердить неполные данные является защитой.

Финальные веса запрещены для дат до обучения; история должна доходить до даты
расчёта, актуальность складского снимка проверяется отдельно. Свежие данные
не возникают из изменения даты в форме.

Stockout и клиентские события в этом HTTP-пути не восстанавливаются.
Их [отдельные проверки](../model/regular_forecast/README.md).
[Метрики SE и IEK](../model/forecast_v2/REPORT.md).

## 4. Диагностика запуска

| Симптом | Проверка |
| --- | --- |
| Не устанавливается CatBoost / pandas | Используйте Python 3.12 и новое виртуальное окружение |
| Интерфейс открыт, API недоступен | Проверьте API на 8000; используйте frontend через Vite на 5173 |
| Порт занят | Откройте уже запущенный Tirek либо остановите свой предыдущий сервер |
| `calculation_allowed=false` | Прочитайте отчёт, проверьте роли, имена и структуру XLSX |
| `needs_data` / `needs_review` | Прочитайте причины в карточке; неизвестное значение не равно нулю |
| Ошибка контрольной суммы весов | Восстановите согласованный комплект `model/forecast_v2/artifacts/` |
| PowerShell не разрешает `dev.ps1` | Используйте раздельные команды API и frontend из README |

Для изоляции перед запуском API задайте в PowerShell
`$env:DATA_DIR = './data/jury-check'`, в bash — `export DATA_DIR=./data/jury-check`.
Переменные из `.env.example` — образец, автоматическая загрузка не подразумевается.
