# Tirek frontend

React + TypeScript + Vite. Русский интерфейс, Manrope (шрифт поставляется локально), Phosphor, Recharts, Radix Dialog.

Из `frontend/`:

```powershell
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Backend должен работать на порту 8000; `/api` проксируется через Vite. Адрес другого API задаётся через `VITE_API_URL` в `frontend/.env.local` (полный базовый URL с `/api/v1`). При сетевой ошибке показывается ошибка, демо не включается автоматически.

## Экраны

- `/`: обзор, состояние запаса, история отдельного товара, очередь внимания.
- `/recommendations`: поиск, категории, срочность, отбор позиций, карточка и корректировка.
- `/data`: drag-and-drop XLSX, скачивание синтетического учебного набора, чтение JSON-контекста из файла, отчёт импорта.
- `/approvals`: утверждённые снимки и повторный экспорт.
- `/settings`: аккаунт, смена пароля, выход, возможности текущего бэкенда и ограничения демонстрации.

До входа любой маршрут показывает регистрацию/авторизацию. Регистрация создаёт
личное рабочее пространство с отдельными файлами, расчётами и решениями. Название
компании задаётся при регистрации; приглашения коллег и восстановление пароля по
почте пока не реализованы. В настройках доступна смена пароля с завершением других
сессий.

Сессия хранится в HttpOnly cookie; запросы используют `credentials: include`, а
изменения — `X-CSRF-Token`. Токен CSRF хранится только в памяти приложения, данные
входа не сохраняются в localStorage. `GET /api/v1/auth/me` восстанавливает сессию;
`POST /auth/register`, `/auth/login`, `/auth/logout`, `/auth/password` управляют
аккаунтом относительно того же префикса `/api/v1`. Ответ 401 на запрос рабочего
пространства возвращает экран входа, не подменяя данные демонстрацией.

Кнопка «Помощник» открывает диалог; его можно вызвать также из карточки товара.
`GET /api/v1/assistant/status` сообщает реальный режим, `POST /api/v1/assistant/chat`
возвращает ответ. Без настроенного провайдера показывается локальная справка,
а не имитация ИИ. Контекст расчёта отправляется только после отдельного выбора
пользователя. Помощник не меняет количества и не утверждает заказы.

«Скачать учебный набор» обращается к авторизованному
`GET /api/v1/samples?supplier_id=systeme-electric|iek`. Архив содержит синтетические
XLSX, `additional-context.SYNTHETIC.json` и пример параметров расчёта. Выбор JSON
(меньше 2 МБ) только читает файл локально; передача выполняется при нажатии
«Проверить и загрузить». Учебные XLSX запускают настоящий модельный код, тогда как
встроенный набор `demo-systeme-v1` использует заранее подготовленные числа.

Типы API генерируются из общего `contracts/openapi.yaml`; бизнес-формулы закупки в браузере отсутствуют.

Для нормализованного набора форма расчёта передаёт режим, исходные коды категорий,
срок поставки, бюджет и JSON-массивы политик/экономики/прироста. Дата берётся из
набора. Переход из отчёта импорта выбирает этот набор. Демо остаётся отдельным
сценарием; режим и происхождение данных показаны независимо.

```powershell
npm run generate:types
npm run build
```

## Браузерные проверки

Нужны полный backend/ML на Python 3.12 (`backend/requirements-ml.txt`) и Chromium.
Установка браузера один раз, из `frontend/`:

```powershell
npx playwright install chromium --no-shell
```

Две группы требуют разных режимов API, поэтому их запускают последовательно.
Не запускайте все файлы одной командой `npx playwright test` против одного сервера.
Оба режима используют API на 8000 и Vite на 5173. Браузерные тесты меняют базу;
для каждого прогона создавайте отдельный `DATA_DIR`, а после проверки возвращайте
рабочий сервер с обычными настройками.

### Сервис с авторизацией (по умолчанию)

Из корня репозитория подготовьте синтетические XLSX и запустите серверы в первом
терминале. Указанный каталог образцов нужен `ml-workflow.spec.ts`:

```powershell
.\.venv-ml\Scripts\python.exe scripts/generate_sample_data.py --output .local-data/samples
.\.venv-ml\Scripts\python.exe scripts/generate_sample_data.py --supplier iek --output .local-data/samples-iek
$env:TIREK_AUTH_DISABLED = '0'
$testDataDir = Join-Path $PWD ('.local-data/e2e-service-' + [guid]::NewGuid().ToString('N'))
.\scripts\dev.ps1 -DataDir $testDataDir
```

Во втором терминале, из `frontend/`:

```powershell
npm run test:e2e:service
# npm run test:e2e запускает ту же группу
```

Проверяются регистрация, восстановление сессии после reload, смена пароля,
выход/вход, мобильные ошибки авторизации, помощник и полный путь учебных XLSX:
импорт → фактический ML-прогноз → обоснование → утверждение → CSV → история.
Сценарии создают случайные тестовые аккаунты. Свежая изолированная база при
повторном прогоне также предотвращает упор в ограничение частоты регистрации.

### Регрессия прежнего интерфейса без авторизации

Остановите предыдущие серверы (`Ctrl+C` в первом терминале), затем из корня:

```powershell
$env:TIREK_AUTH_DISABLED = '1'
$testDataDir = Join-Path $PWD ('.local-data/e2e-legacy-' + [guid]::NewGuid().ToString('N'))
.\scripts\dev.ps1 -DataDir $testDataDir
```

Во втором терминале, из `frontend/`:

```powershell
npm run test:e2e:legacy
```

Эта группа намеренно использует общий локальный demo без аккаунта: desktop/mobile,
поиск, пустые значения, drawer и Escape, ошибки партии, корректировку, утверждение,
реальное скачивание CSV, историю, ошибки сети/HTML/JSON, импорт и параметры формы.
`TIREK_AUTH_DISABLED=1` предназначен только для изолированной локальной регрессии.
Перед обычным запуском верните `TIREK_AUTH_DISABLED=0` и рабочий `DATA_DIR`.

Для проверки адаптера нужен backend с `backend/requirements-ml.txt`. Тест XLSX
генерирует файл в памяти через `.venv-ml` (или `.venv`); другой Python можно указать
через `TEST_PYTHON`. Контракт формы реального набора проверяется на явном UI-fixture,
а не на партнёрских данных. Перед повторным прогоном тест отчёта явно выбирает демо,
поэтому наличие ранее загруженных файлов не меняет результат.

Скриншоты сохраняются в `test-results/`, в Git не входят. Следующий запуск Playwright
очищает каталог результатов, поэтому нужные доказательства скопируйте до смены
группы. Используется полный Chromium (`channel: chromium`), один worker; серверы
автоматически конфигурацией Playwright не поднимаются.
