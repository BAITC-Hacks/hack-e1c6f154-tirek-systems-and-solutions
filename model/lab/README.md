# Адаптер источников SE и аудит данных

`load_se(directory)` читает все шесть исходных XLSX в режиме read-only и возвращает дневные продажи, **отдельные** месячные таблицы, кратность, текущий снимок, единицы измерения и агрегированный аудит. Адаптер не обучает модель, не создаёт веб-сервис и не меняет файлы партнёра.

Запуск из корня репозитория:

```bash
python -m model.lab.sources '/path/to/Systeme electric' --audit-output model/lab/source_audit.json
python -m unittest model.lab.test_sources -v
python -m unittest discover -s model -p 'test_sources.py' -v
```

Сохранённый `source_audit.json` содержит хеши шести файлов, счётчики, покрытие и агрегированную сверку. Построчных продаж, SKU и клиентских идентификаторов в нём нет. Все 18 тестов используют синтетические рабочие книги и временные файлы; частные данные для запуска тестов не нужны.

| Источник | Что используется | Ограничение |
| --- | --- | --- |
| Динамика продаж | Положительные расходные накладные с 2025 года, единица `шт`, склад Алматы | Это наблюдаемые продажи, а не полный скрытый спрос. Возвраты не превращаются в продажи через `abs()` |
| Месячные продажи 2024–2026 | Отдельный признак прошлого года, рассчитанный из месячных величин | Не складываются с дневными продажами и не заменяют дневные целевые значения |
| Месячные остатки | Остаток за предшествующий завершённый месяц как вспомогательный признак | Пустая ячейка означает неизвестное значение; это не история ежедневных stockout |
| Сезонность | Безразмерный индекс из 12 исходных месяцев предыдущего полного года | Единица исходного агрегата не подписана, денежная природа не подтверждена. Готовые коэффициенты с использованием будущих лет не используются |
| MOQ | Поле `Кратность` отдельной выгрузки | Это кратность заказа, а не доказанная минимальная партия. Исторические даты действия отсутствуют |
| Товар в пути на 22.09.2026 | Текущий остаток, резерв, свободный остаток, категория и ожидаемая поставка 24.09 | Область складского учёта не подтверждена; текущий снимок не является историческим признаком |

## Проверенные ограничения реальных файлов

- В дневной истории 565 SKU. Месячные продажи и кратность покрывают 545 из них; текущий снимок покрывает 470. У 95 продававшихся SKU нет текущего профиля — для них нельзя достоверно рассчитать текущий заказ.
- Текущий снимок содержит 497 профилей. У 23 не подтверждена единица, у 28 отсутствует кратность. Эти значения остаются неизвестными.
- Для всех 497 профилей выполняется `Остаток − Зарезервировано = Свободный остаток`. Резерв нельзя вычитать второй раз из уже свободного остатка.
- Сумма четырёх складских компонентов совпадает с полем `Остаток` лишь у 4 профилей. Адаптер не складывает эти компоненты с общим остатком: их смысл требует уточнения.
- Для 545 общих SKU сопоставлено 10 642 завершённых SKU-месяца. У 4 526 ячеек суммы расходятся: положительные дневные накладные дают 6 487 558 единиц, месячный отчёт — 3 081 305 на сравниваемых ячейках. Семантическое соответствие и фильтры выгрузок не подтверждены. Использование месячного признака требует отдельной оценки качества; смешивать целевые значения нельзя.
- В месячных продажах 323 отрицательные ячейки оставлены неизвестными. Предположение «пустая месячная продажа = 0» явно записано в аудите; у остатков такого предположения нет.
- Встроенная в месячные продажи кратность конфликтует с отдельной выгрузкой у 26 SKU. Используется отдельное поле `Кратность`; актуальность его даты всё равно требует проверки.
- SKU хранятся строками: в истории 102 кода с ведущим нулём. Числовые ячейки кода отклоняются, поскольку исходные ведущие нули невозможно безопасно восстановить. Единицы сверяются при объединении.
- Полных дубликатов строк накладных нет. Есть 242 группы с несколькими строками одного документа и SKU. Это не доказательство дублирования: без ID строки они сохраняются. Для справочников разрешено исключение только полностью одинаковых строк, а конфликтующие строки одного SKU вызывают ошибку.

## Защита от будущих данных

`enrich_features(frame, sources)` работает с отдельной датой каждой строки, в том числе при нескольких датах прогноза в одной таблице. Месячное значение допускается лишь после окончания месяца; публикационная задержка и история исправлений отсутствуют. Поэтому защищены от использования будущих **периодов**, но исторические версии выгрузок нельзя подтвердить.

`monthly_prior_window` распределяет месячную величину прошлого года пропорционально числу соответствующих дней только внутри признака. Он не создаёт дневную историю, дневную разметку или наблюдения для обучения. Неполное покрытие окна возвращает `NaN`.

`current_profiles_at(sources, as_of)` отдаёт снимок только начиная с его даты и возвращает копию. Проверка свежести — отдельная политика потребителя: этот метод не объявляет старый снимок актуальным. Год ETA принят равным году датированного снимка и явно помечен как предположение.

Стоимость `СС реал` хранится как `reported_cost_unverified`. Значения `unit_cost`, цены продажи, срока поставки, минимальной партии и независимого прогноза роста остаются `None`. Категория сохранена как исходная метка, без выдуманного соответствия ABC или уровню сервиса.

На этих шести файлах можно проверить прогноз наблюдаемых продаж, сезонные признаки, доступные остатки, датированное поступление и кратность. Нельзя доказать коррекцию упущенного спроса по точным stockout, исключение разовых заказов конкретного клиента, экономическую оптимальность или учёт материальных обязательств: необходимых полей нет. Эти сценарии проверяются отдельно на синтетических данных и должны быть явно отличены от проверки на реальных данных.
