## Контракт входа

- `horizon_days` — строго `int`, от 1 до 366, без выхода за календарь Python.
  `bool`, float, нулевые, отрицательные и чрезмерные горизонты отвергаются.
- Даты — канонические `YYYY-MM-DD`. `launch_date <= as_of`; история и события
  не предшествуют запуску товара и не находятся после cutoff. Аналоги могут
  предшествовать запуску, но не cutoff.
- История должна иметь строго возрастающие даты. Перемешанные и повторяющиеся
  даты отвергаются; контракт не зависит от случайного порядка строк импорта.
- `history.complete` — строго boolean. Числовые поля конечны и неотрицательны;
  availability остаётся в `[0, 1]`. Типы контейнеров и строковых идентификаторов
  проверяются до использования, ошибочный вход даёт `ValueError`.
- Акции: `announced_at <= as_of`, `announced_at <= start_date <= end_date`,
  multiplier строго положительный. Объявленная до cutoff будущая акция допустима.

## Отказы и числовая устойчивость

Валидатор прогноза проверяет не только каждый день, но и конечность суммы горизонта.
`finite_sum` использует `math.fsum` и переводит нечисловые/неконечные/переполненные
суммы в `ValueError`. Вычисления суммы прогноза и дневных абсолютных ошибок
находятся в защищённом пути строки оценщика.

Агрегатор проверяет накопленные суммы абсолютной ошибки, signed error и дневной
ошибки. При переполнении возвращает `aggregation_error`, null для метрик и
полное число затронутых строк. Оценщик помечает все строки затронутой единицы
измерения как failed, сохраняет их реальные цели и отдельный `aggregation_failures`,
обнуляет только недоступные прогнозные поля до null. Затем сохраняет три артефакта
и возвращает код 2. Подмножество численно успешных строк не выдаётся за полный запуск.
Если переполнится сама сумма целей, она недоступна (`null`), но исходные строки
целей сохраняются; обычные конечные знаменатели сохраняются без изменений.

Два полных development-only regression-прогона подтверждены:

| Прогноз | Причина | Строк/failed | WAPE/MAE | Артефакты | Код |
|---|---|---:|---|---|---:|
| `1e308` каждый из 28 дней | переполнение горизонта | 12/12 | null | JSON, CSV, Markdown | 2 |
| `1e306` каждый из 28 дней | конечные горизонты `2.8e307`, переполнение общей ошибки | 12/12 | null | JSON, CSV, Markdown | 2 |

В обоих случаях знаменатель реализации положительный, все целевые строки
сохранены, `forecast_target_met=false`. Парные MH4 получают null для failed
прогнозов и не вызывают `ceil(inf)`.

## Метрики и совместимость CLI

CLI-флаги сохранены. При итоговой интеграции root сменил адаптер по умолчанию на
`model.testbed.seasonal:forecast`, manifest на `corrected-freeze.json` и добавил
группировку по SKU. Старый baseline доступен явным `--adapter`. JSON schema стала
`testbed-report-v2.1`; добавлены `aggregation_failures` на верхнем уровне,
`units` и `aggregation_error` в агрегатах. Все существующие числовые ключи
сохраняются. В overall и каждой группе добавлены:

- `mae_realized`, `mae_expectation`: сумма абсолютной ошибки горизонта / число SKU-прогнозов;
- `mean_signed_error_realized`, `mean_signed_error_expectation`: signed error / число SKU-прогнозов;
- `daily_mae_realized`, `daily_mae_expectation`: дневная абсолютная ошибка / (число SKU-прогнозов × горизонт).

Markdown показывает MAE, bias, дневной MAE и WAPE отдельно. WAPE и MAE
не суммируются по разным единицам: общий mixed-unit агрегат неопределён,
содержит явную причину и приводит к коду 2. `groups.unit` остаются доступны.
Для нулевого знаменателя WAPE и bias равны null, но абсолютная ошибка и MAE
сохраняются. Пустой набор имеет MAE=null. Любой failed прогноз делает метрики
всей соответствующей группы недоступными; знаменатель не сокращается.
