# Тестовая среда закупок v2.1

Программная среда без UI, HTTP и внешних Python-пакетов. Область изменений —
`model/testbed/`. Требования: [матрица](../../docs/requirements-matrix.md),
[правила решения](../../docs/decision-rules.md) и предоставленный кейс партнёра.

Это воспроизводимые сценарии, сменные адаптеры и независимые ожидаемые ответы.
Reference calculator не является подключённым производственным расчётным модулем.
[Разбор ошибок и исправлений v2.1](repairs/v2.1/REPORT.md) включает проверку PDF и
12 исходных Excel, результаты испытаний и оставшиеся ограничения.

## Запуск

Из корня worktree; стандартная библиотека Python 3.10+, сохранённая версия — 3.14.4.
Для проверки freeze нужна именно указанная в нём версия Python.

```sh
python3 -m unittest discover -s model/testbed/tests -v
python3 -m model.testbed.run evaluate --split development --require-target --output model/testbed/reports/v2.1/development
python3 -m model.testbed.run evaluate --split regression --require-target --output model/testbed/reports/v2.1/regression
python3 -m model.testbed.run check-business --output model/testbed/reports/v2.1/business.json
```

`--require-target` возвращает **3**, если WAPE >10%; это ожидаемый измеренный
результат, а не падение среды. Код **2** — ошибка адаптера, чисел, бизнес-проверки
или парной MH4. Без `--require-target` высокий WAPE не меняет код завершения.

Development seeds: **101, 202, 303**. Прежние final seeds **909, 1337, 2027, 4099**
уже просмотрены. Для изменённой версии разрешён только явно обозначенный
`regression`; `--split final` отклоняется. Новое независимое подтверждение качества
требует заранее утверждённого нового holdout. Параметры v2.1 не подбирались по
результатам этих final seeds; сезонный адаптер выбран по требованию MH2 до dev-оценки.

`freeze-v2.1.json` фиксирует кандидата перед regression. Для другого адаптера:

```sh
python3 -m model.testbed.run freeze --adapter my_package.adapter:forecast --artifact /path/to/weights.bin --manifest model/testbed/external-freeze.json
python3 -m model.testbed.run evaluate --split regression --adapter my_package.adapter:forecast --manifest model/testbed/external-freeze.json --output model/testbed/reports/external-regression
```

Freeze содержит SHA-256 Python-файлов, protocol, фикстур, модулей адаптеров, явно
перечисленных зависимостей/весов, версию Python и исходный commit. Он не перезаписывается.
Владелец внешней функции перечисляет все транзитивные зависимости через `--artifact`.
Manifest — локальный аудируемый протокол, не защита от намеренного изменения файлов.
Старые `freeze.json`, `reports/development/`, `reports/final/` и аудиты сохранены.
Исторические audit-скрипты воспроизводят старые дефекты на commit `771aa8e`;
они не являются приёмочными тестами исправленной версии.

## Проверка предоставленных файлов

```sh
python3 -m model.testbed.run inspect-sources --input-dir /path/to/папка --output model/testbed/reports/v2.1/source-readiness.json
```

Инспектор читает два ZIP и 12 XLSX в памяти, проверяет фиксированные схемы всех
14 листов, даты, единицы, пропуски, отрицательные количества, ошибки Excel,
кеш формул, внешние ссылки и покрытие артикулов между источниками. Записываются
хеши и агрегаты; исходные книги, строки и идентификаторы товаров/документов не
копируются в репозиторий. Отсутствующий файл или изменённая схема дают код 2.
Совпадение схемы не означает готовность к закупке.

Это инспектор данной партии, **не универсальный импортёр**. Отчёт явно отделяет
найденные поля от недостающего контекста: клиентские метки, точные stockout-интервалы,
срок нового заказа, политика категории, подтверждённая экономика/обязательства.
ETA открытого заказа не становится сроком нового. Месячный нулевой остаток не
становится месяцем отсутствия; отрицательные продажи не превращаются в модуль,
пропуски — в ноль. Файл SE с названием MOQ содержит кратность, а не отдельный MOQ.
Формула AP3 в своде SE суммирует 13 месяцев под подписью «12 месяцев» и помечается.
По наблюдаемым Excel нельзя измерить WAPE скрытого регулярного спроса: такой истины
и подтверждённых проектных меток в них нет. Backtest наблюдаемых продаж — другая задача.

## Данные и граница модели

1. Публичный JSON: прошлые дневные наблюдения и их полнота/доступность, документы
   с псевдонимами клиентов, SKU/единица/склад/поставщик/категория/дата запуска,
   прошлый аналог и объявленные до cutoff акции.
2. Только оценщик: скрытый реализованный регулярный спрос и его математическое
   ожидание, включая потери при недоступности.
3. Отдельно: разовые проекты. Исторические документы наблюдаемы без проектной метки;
   будущие проекты не входят в регулярную цель.

ID документов непрозрачны и не кодируют тип покупки; события перемешаны отдельным
потоком RNG, не изменяющим спрос. Клиентские ID не являются постоянными метками класса.
Allowlist проверяет вложенные поля, ISO-даты, типы, горизонт, доступность, положительные
коэффициенты акций, отсутствие будущих данных и дубликатов. Документы полного
синтетического пакета должны согласоваться с дневными наблюдениями. Неполная история
и отсутствие истории нового товара разрешены; отсутствие сведений не означает ноль.

Адаптер получает только публичный JSON через stdin отдельного subprocess: без seed,
названия сценария, параметров генератора или будущей истины. Его мутации не меняют
данные оценщика. Это граница данных для доверенного кода, **не OS sandbox**: общий
filesystem и известный генератор не защищены от злонамеренной внешней функции.
Происхождение и временные границы обучающих данных внешней модели проверяет её владелец.

```sh
python3 -m model.testbed.run export-development --scenario split_project --seed 101 --output model/testbed/sample
```

Только `model-input.json` передаётся модели. `evaluator-only/` — файлы оценщика.

## Прогнозные адаптеры и сценарии

```python
def forecast(request: dict) -> dict[str, list[float]]:
    # Exactly every requested SKU; horizon_days finite nonnegative daily values.
    return {item["sku"]: [1.0] * request["horizon_days"] for item in request["items"]}
```

```sh
python3 -m model.testbed.run evaluate --split development --adapter my_package.adapter:forecast --output model/testbed/reports/external-dev
python3 -m model.testbed.run evaluate --split development --adapter model.testbed.baseline:forecast --output model/testbed/reports/v2.1/baseline-control
```

Функция доступна через Python path. Timeout — 30 секунд на вызов, stdout функции
перенаправляется в stderr. Ошибки, NaN/inf, переполнение, отрицательные значения,
неполный набор SKU/горизонт сохраняют строки с ошибкой; общая метрика становится
null, вместо оценки только успешной части.

По умолчанию `seasonal:forecast`: лаг 364 дня, семь опор того же дня недели в окне
±21 день, рост по 56 сопоставимым прошлогодним дням. Нужны span≥420 дней, ≥28 пар
и ≥4 опоры; иначе используется среднее по доступности за последние 56 календарных
дней или явный аналог. Полностью неизвестный спрос без аналога даёт ошибку.
Параметры заданы до измерений, перечислены в [protocol.json](protocol.json).
Контрольный `baseline:forecast` оставлен как доступный алгоритм без годовой сезонности.

Оба примера очищают крупное клиентское окно 7 дней (>8 дневных медиан), сохраняя
клиента с повторяемостью ≥3 недель; нормализуют известные акции и доступность.
Это эвристика, а не истинная классификация проектов. Seasonal может ухудшать редкий
спрос, сохранять шум прошлогоднего ряда и не предсказывает неизвестный шок.

| Сценарий | Что проверяется |
|---|---|
| stable | Стабильный Poisson-спрос и недельный профиль |
| seasonal_growth | Годовая сезонность и устойчивый рост |
| intermittent | Редкое событие × случайный размер; нулевые цели сохранены |
| new_product | Ноль/8 дней истории и прошлый аналог |
| full_stockout / partial_stockout | Полная и частичная цензура продаж |
| single_project / split_project | Разовая покупка, в том числе 15 документов за 3 дня |
| recurring_client | Регулярный крупный клиент сохраняется |
| known_promotion | Объявленная акция в истории и будущем |
| demand_shock | Неанонсированный будущий скачок без предвестника |
| combined | Сезонность, рост, stockout, проект, акция, скачок |

560 дней истории, горизонт 28 дней, 4 SKU, cutoff 2025-07-01 и 2026-04-01.
288 строк development и 384 regression. Это независимые ансамбли, не непрерывный
симулятор движения склада. Регулярный спрос, проекты, цензура и ID используют
отдельные потоки SHA-256/Random. Парные stable/stockout/project разделяют латентный
путь намеренно; строки нельзя считать независимой статистической выборкой.

## Метрики и доказательства

Основная WAPE = Σ|сумма прогноза SKU за горизонт − сумма скрытого регулярного
спроса| / Σ скрытого регулярного спроса. Отдельно WAPE по математическому ожиданию,
смещение, абсолютные ошибки, нулевые цели и дневная WAPE. Горизонтная метрика
допускает компенсацию ошибок между днями; дневная — нет. Агрегируются объёмы и
ошибки, а не среднее процентов. При нулевом знаменателе WAPE null; строка остаётся.
Все прогнозные SKU в штуках; разные физические единицы не складываются в одну WAPE.

Отчёты `report.json`, `rows.csv`, `report.md` содержат все SKU, сценарии, seeds,
cutoff, scenario×seed и бизнес-проверки. Ожидание условно на скрытых будущих шоках,
поэтому не полностью предсказуемо по публичным данным. **Цель WAPE ≤10% не
гарантируется. 90% пройденных тестов не означает 90% качества прогноза.**

Независимое воспроизведение по датам и Decimal без вызова production aggregate:

```sh
python3 model/testbed/repairs/v2.1/verify.py --report-dir model/testbed/reports/v2.1/development --report-dir model/testbed/reports/v2.1/regression --output model/testbed/reports/v2.1/verification.json
```

## Закупочный контракт

[87 фикстур](fixtures/business_cases.json): полные входы и независимо заданные
ожидаемые поля ответа. Их ожидаемые количества не вычисляются тестируемой функцией.
33 граничных примера взяты из независимого review-2. Дополнительно checker проверяет
схему и согласованность статусов/количеств, поставщиков, единиц, партий, стоимости,
бюджета, объяснений и доказательств каждого применённого правила; шесть мутаций
заведомо неверного ответа не должны проходить.

```sh
python3 -m model.testbed.run check-business --calculator my_package.adapter:calculate --output model/testbed/reports/external-business.json
```

`calculate(request)->dict` — локальный контракт; преобразование производственного
модуля задаёт его адаптер. Точного соответствия HTTP OpenAPI не заявляется.
Reference допускает экономические q=0/1, нулевую цену и нулевой lead для граничных
тестов; HTTP-схема местами строже. В отчёте всегда виден `reference_only` или
`external_adapter`. Проверки не отправляют и не утверждают заказ.

Покрыты запас, резерв/net stock, поступления и сроки, MOQ/кратность, категории,
внешний прирост/уже включённый коэффициент, обязательства, экономика разных товаров,
бюджет, пропуски, физические единицы и упаковки. Цена задаётся за базовую единицу;
MOQ/кратность — за order_unit с явной конверсией. Входы разбираются через Decimal; затем Fraction точно считает
деньги, пропорции и временные остатки до округления закупки. Quantum/multiple/factor
поддерживаются в [1e−12, 1e12], MOQ в [0, 1e12]; вне диапазона — DATA-01. Известное ограничение
соблюдается даже при неизвестном втором; результат остаётся `needs_review`.

Свободный остаток уже очищен от резерва. Из обязательств добавляется только неучтённая
часть. Поступление — в начале дня, потребление — в конце; день1 следует за as_of,
lead=0 означает до day1. Поздний приход не уменьшает закупку ценой скрытого провала
между ETA нового заказа и этим приходом. Ранний дефицит до ETA остаётся показан.

Квантиль берётся из распределения **за весь горизонт**, по индивидуальной экономике
и минимуму категории. Допуск массы вероятности 1e-9 обрабатывается нормализацией.
Target распределяется пропорционально daily_mean (`planning_profile`), это допущение,
не калиброванные дневные квантили. В ответе отдельно `aggregate_need`,
`temporal_lower_bound`, траектории mean/planning с заказом и без, неудовлетворённый
спрос и `mean_risk_after_order`. Низкий экономический target не заменяется полным
средним автоматически. Внешний прирост масштабирует распределение пропорционально
изменению среднего — ещё одно явное упрощение reference.

Парная MH4 сравнивает прогноз и ceil(forecast) в фиксированном контексте
stock=inbound=0, MOQ=multiple=1; это отдельный узкий контроль, не весь калькулятор.
Производственный движок, импорт в1С, approval/revision, AI fallback, эндогенный
stockout, возвраты, замещение SKU, стоимость доставки и оптимизация бюджета
не проверяются этой синтетической средой. Сырые файлы партнёра не исправлялись.
