# Обученная модель продаж Systeme Electric

Эта страница описывает первую версию сохранённого CatBoost. Дополнительные модули:
[аудит шести источников](lab/README.md), [регулярный спрос и stockout](regular_forecast/README.md),
[математика заказа и проверки](decision/README.md). Их функциональные тесты не
заменяют измерение ошибки прогнозирования; достижение WAPE ≤10% пока не доказано.

Обучен и сохранён CatBoost для прогноза количества продаж на следующие 28 дней.
Данные реальные: 76 997 положительных строк расходных накладных, 565 товаров,
склад Алматы, единица «шт», 04.01.2025–22.09.2026. Это модель наблюдаемых продаж;
расчёт заказа, интерфейс и HTTP-сервис в этом изменении не реализуются.

**Качество пока не подтверждает замену baseline:** сезонный базовый прогноз лучше
на выбранной validation-выборке и в сумме двух последующих проверочных периодов.
Обученная ML-модель сохранена отдельно; выдача показывает оба прогноза и явно указывает
предпочтительный метод. Baseline не называется ML.

## Сохранённые результаты

- [se-demand-28d.cbm](artifacts/se-demand-28d.cbm) — реальные обученные веса CatBoost, около 7.9 MB.
- [manifest.json](artifacts/manifest.json) — контрольная сумма весов, версия, признаки, параметры и преобразование целевой переменной.
- [evaluation.json](artifacts/evaluation.json) — аудит входа, даты обучения, validation, оба тестовых окна, метрики и ограничения.

Исходный XLSX и построчные продажи в Git не добавлены. При загрузке модели проверяется
SHA-256. Прогнозы по товарам формируются локально из совместимой выгрузки.

## Фактическая проверка

Кандидаты выбирались по WAPE на окне 30.06–27.07.2026. Из трёх ML-кандидатов выбран
ScaledPoisson: CatBoost с Poisson loss и нормализацией целевого количества относительно
`max(сумма прошлых 84 дней / 3, 10)`. Итог умножается на тот же масштаб из прошлого.
500 деревьев, глубина 6, learning_rate 0.05, seed 42. На validation WAPE ML — 26.34%,
baseline — 25.22%. Параметры baseline: 50% продажи в сопоставимом окне 364 дня назад
и 50% среднего темпа за последние 56 дней; без годовой истории — средний темп за 56 дней.

| Прогнозируемый период | WAPE CatBoost | WAPE baseline | MAE CatBoost, шт. | MAE baseline, шт. |
| --- | --- | --- | --- | --- |
| 28.07–24.08.2026 | 69.12% | 59.20% | 351.81 | 301.35 |
| 25.08–21.09.2026 | 35.51% | 22.99% | 263.16 | 170.35 |
| Оба периода вместе | 49.19% | 37.73% | 307.49 | 235.85 |

WAPE = сумма абсолютных ошибок / сумма фактических количеств; меньше — лучше.
Это не «процент правильных прогнозов». Все строки имеют одну единицу, разные единицы
и поставщики в эту метрику не смешивались. Агрегация двух периодов взвешена по объёму,
а не получена простым средним двух процентов.

Перед каждым прогнозом обучение использует только примеры, у которых полностью
закончились будущие 28 дней целевого окна. Случайного разделения строк нет. SKU,
ещё не наблюдавшиеся к дате прогноза, не подмешиваются в прошлую выборку.
Последний день выгрузки исключён из train/test-целей: полнота дня не подтверждена.
Для текущего прогноза свежие признаки включают доступные продажи 22.09.2026.

Два проверочных окна уже просматривались при разработке. Выбор финального кандидата
делался по validation, но для принятия в эксплуатацию нужен новый, ещё не просмотренный
период и дополнительная проверка на данных о доступности товара.

## Запуск с сохранёнными весами

Python 3.12; из корня репозитория:

```sh
python3.12 -m venv .venv-model
.venv-model/bin/pip install -r model/requirements.txt
.venv-model/bin/python model/infer.py --sales "/path/to/Динамика продаж_Syseme Electric_2025-2026.xlsx" --model-dir model/artifacts --output /tmp/se-forecast.csv
```

В CSV: код, склад, единица, дата данных, начало/конец горизонта, модель,
`forecast_ml`, `forecast_baseline`, `selected_method`, `selected_forecast`,
`ml_p10_estimate`, `ml_p50_estimate`, `ml_p90_estimate` и длина наблюдаемой истории.
Значения прогнозов дробные: это ожидаемое количество, а не округлённая закупочная партия.

`selected_method=seasonal_blend` выбран на validation. Интервалы с префиксом `ml_`
относятся только к ML, не к выбранному baseline. Они получены по нормализованным
ошибкам validation за полный горизонт; сумма дневных P90 не используется.
Покрытие предполагаемого 80%-интервала на проверочных окнах составило 75.58% и 81.06%.
Калибровка по каждому SKU не доказана.

Совместимая свежая выгрузка должна сохранять историю с 2025 года и порядок колонок:
Дата, Номер, Документ, Код, Номенклатура, Ед., Склад, Количество. Прогнозный горизонт
начинается на следующий день после последней продажи в файле. Это дата фактических
данных, а не системное «сегодня». Изолированная выгрузка одного нового дня недостаточна.

## Повторное обучение

```sh
.venv-model/bin/python model/train.py --sales "/path/to/Динамика продаж_Syseme Electric_2025-2026.xlsx" --output /tmp/se-model --predictions /tmp/se-new-forecast.csv --iterations 500 --threads 4
.venv-model/bin/python -m unittest discover -s model -p 'test_*.py' -v
```

`infer` пересчитывает признаки на свежей истории без переобучения. `train` явно обучает
новые веса и повторяет временную проверку; автоматического самообучения нет.
Пять тестов проверяют отсутствие будущего в признаках, длину и границы target,
недопустимые короткие окна и отсутствие утечки ещё не появившихся SKU.

## Границы этой модели

- Возвраты и коррекции не превращаются в продажи через abs(); целевая переменная —
  положительное количество отгрузок, не выручка, не маржа и не чистое количество после возвратов.
- Клиентских ID нет. Робастные признаки ограничивают влияние крупных дней в части
  признаков, но надёжное исключение клиентских разовых заказов ещё не реализовано.
  Реальные целевые значения не обрезались ради улучшения метрик.
- Точных stockout-интервалов нет. Модель не обучена на восстановленном скрытом спросе;
  низкие продажи при отсутствии товара могут занижать прогноз.
- Остатки, путь, категории закупочной политики, цена, MOQ, пороги внимания и LLM judgement
  относятся к отдельным модулям из ТЗ. Нельзя выдавать этот прогноз за готовый заказ.
- Более ранние помесячные данные не смешивались с детализацией; дополнительная история
  2024 года, IEK и клиентские/stockout-данные остаются работой для следующей версии модели.
